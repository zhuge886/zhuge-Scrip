# 地区、类型与自动尝试

## 数据来源

2026-10-23 读取国网官网公开静态资源：

- [官网入口](https://www.95598.cn/osgweb/)
- [地区选择与户号查询组件](https://www.95598.cn/osgweb/js/chunk-0af2ed08.bf1146e5.js)：其中 `judgeproCodeName` 映射地区路由，河北城市选择分别使用 `13102` 和 `16101`。
- [户号选择组件](https://www.95598.cn/osgweb/js/chunk-c32f2cf4.09f9cab9.js)：其中 `elecTypeCode` 对应下表名称。
- [官网主脚本](https://www.95598.cn/osgweb/js/app.ebdb9da9.js)：包含地区字典和缴费查询路径配置。

只提取路由/类型事实，没有将这些网站脚本加入可导入项目。地区常量不是由行政区划代码拼接生成；没有推算供电单位代码。官网来源的路由仍需在当前 App 协议中实测兼容性。

## 类型的含义

这些场景用于余额请求的 `sceneType`，不能与账单返回的 `consType` 预付费/后付费字段混为一谈。原协议的日用电请求还会按既有规则转换 `consType`，没有直接把场景名称当成计费方式。

## 官网资料接口与当前实现

公开源码配置了：

- 地区字典 `/osg-open-om0001/member/arg/020390124`，参数 `pCodeValue`。
- 户号查询 `/osg-open-uc0001/member/c9/f03`。
- 缴费资料 `/osg-wp0002/member/charge/getElecUserChargeList`，使用户号列表、省份路由和会话令牌。

这些是官网渠道的路径，不能据此假定它们可直接套用当前 App 的 SM2/SM4 请求封装或令牌。开发环境的公开地区字典直接请求返回 HTTP 405，因此本版没有虚构一个“自动获取全部资料”的已验证接口，也没有新增猜测的 App 端点。

实际尝试仍调用原有 App 余额路径 `emss-bia-balance-front/member/c16/f01`。仅更换同一户号/地区的五种已知场景，单位未知时省略 `orgNo`。服务端是否接受由真实响应决定。返回的数字单位/场景资料会被保存，没有返回的代码保持未指定。

## 成功与停止

必须取得有效金额；仅有 `historyOwe: 0` 不视为有效余额。明确返回的其他户号会拒绝；有可核对户号时选择精确匹配条目，无户号的多条响应也拒绝。

验证码、认证、权限、限流、网络及明确的单位必填错误都停止尝试。只有相关业务参数失败或空结果才换类型。最多五次、串行、间隔 750 毫秒，不扫描地区和单位，不改变服务端绑定关系。

成功只证明某个请求组合被接口接受。若服务端忽略场景参数，则不能据此判断真实类别；单户响应未提供可核对户号时，界面提醒核对官方金额。组合仅在对应配置下重用，小组件不自动执行发现流程。
