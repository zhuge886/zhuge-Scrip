# 1.3.0 单位资料获取与余额查询

## 根因

真实客户端收到 `orgNo不能为空`。1.2.0 将字段改为可选、尝试不同场景，无法满足服务端必需的供电单位资料。

1.3.0 在余额查询前检查单位。缺失时返回可处理的 `org_required`，设置页进入官方网页获取流程，而不是继续发空单位请求。

## 官网渠道

依据此前检查的 [官网入口](https://www.95598.cn/osgweb/)、[户号查询组件](https://www.95598.cn/osgweb/js/chunk-0af2ed08.bf1146e5.js) 和 [主脚本](https://www.95598.cn/osgweb/js/app.ebdb9da9.js)，只调用以下两个只读接口：

| 路径 | 作用 |
| --- | --- |
| `/osg-open-uc0001/member/c9/f03` | 按户号、省份读取可查询的户号资料 |
| `/osg-wp0002/member/charge/getElecUserChargeList` | 查询该户号的缴费资料列表 |

它们在官网的 WebView 内通过官网自身的 `$tools.apiPost` 发起，复用网页渠道的加密和验证。没有把官网路径直接套进 App 的 SM2/SM4 传输。

WebView 采用临时数据容器，只允许 HTTPS 官方域名。登录在官网完成；令牌仅在页面内部参与查询，不返回脚本。脚本不会调用绑定、账户修改或支付提交接口。

## 读取与校验

网页加载后观察以上两个接口中用户手动发起的本户查询，既不新增请求，也不改变其响应。用户点“完成”返回后，优先采用已观察到的有效资料。没有资料时，再通过官网的两个查询接口读取，验证码/认证/限流错误立即停止。

只保存源户号、接口返回的原户号表示、地区、数字 `orgNo` 和可用的场景代码。户名、地址、手机号、验证码、Cookie 和网页令牌不会导入。错误消息中的长标识会遮盖。

要求返回户号与配置精确匹配，地区一致，单位为数字且非空；多组不同资料或只有掩码户号都会拒绝。`acctOrgNo` 是会计单位，不能替代 `orgNo`。

导入会更新资料版本并清除旧金额缓存和查询组合。请求期间若用户换了户号或地区，结果不保存。切换户号也会移除旧资料自动填入的单位和类型。

## App 查询

取得单位后，原 App 协议继续请求 `emss-bia-balance-front/member/c16/f01`。导入保留官网返回的户号表示；跨官网/App 渠道的字段兼容仍需真实账号验证。

类型来源于 [官网户号选择组件](https://www.95598.cn/osgweb/js/chunk-c32f2cf4.09f9cab9.js)：

| 场景 | 代码 |
| --- | --- |
| 住宅 | 01 |
| 店铺 | 02 |
| 电动车 | 03 |
| 企事业 | 04 |
| 新能源 | 05 |

这些是使用场景，不是预付费/后付费方式。仅在已有单位资料且类型未知时最多尝试五次，成功组合供组件复用。验证码、登录、权限、网络、限流和单位必需错误不会通过换类型重试。

## 实际验证的限度

2026-10-25 的云环境匿名空参数检查中，App 余额路径返回 S1001，直接把官网路径放进 App 通道返回 S1005，均不能证明登录后查询可用；官网首页直接读取另返回 HTTP 405。因此改为由用户手机上的官方页面完成渠道登录和查询。页面结构、登录与返回格式目前仅以公开前端快照和模拟验证，仍需 iPhone 实测。
