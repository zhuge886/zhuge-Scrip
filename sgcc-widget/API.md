# 1.4.0 供电公司选择与有限自动尝试

## 供电单位来源

1.2.0 在余额请求中省略 `orgNo`，用户实际收到“orgNo不能为空”。1.3.0 依赖官网查询本户资料，但官网只提供绑定户号，无法解决用户的未绑定户号场景。1.4.0 移除该流程，改用真实公司目录作为候选。

2026-10-25 实查 [国网官网](https://www.95598.cn/osgweb/) 的公共地区目录。依据 [官网查询组件](https://www.95598.cn/osgweb/js/chunk-e247704a.c1808474.js) 和 [主脚本](https://www.95598.cn/osgweb/js/app.ebdb9da9.js)：

```js
// 在官网匿名客户端上下文运行，使用网站自己的 Web 通道。
vm.$tools.apiPost('110101', '/osg-open-om0001/member/c13/f05')
```

参数是行政区域代码，并非户号。实际返回 `code: 1`，`data[].listOrg` 包含 `orgNo: "11401"`、`orgName: "城区供电公司"`、`orgType: "03"`、`pOrgNo: "11102"`。上级 `02` 类为国网北京市电力公司 `11102`；国家电网 `9999` 不是余额查询的本地供电单位。

## 余额协议

运行时不再打开官网，不发送目录查询。仍通过原 App 的加密登录与余额接口：

```text
https://csc-service.sgcc.com.cn:28630/emss-bia-balance-front/member/c16/f01
```

`serviceCode: 0101143`，`source: app`，`target` 为地区代码；`data.list[0]` 传入 `consNoSrc`、`proCode`、`sceneType`、`consNo`、非空 `orgNo`。登录手机号用于获取凭证，手动查询目标始终是用户填写的户号。

官网目录的组织编码与上游 App 请求字段含义一致，但真实未绑定户号的接口权限、原始户号表示、金额返回仍需实际账号验证。没有改用缴费商户编号、会计单位 `acctOrgNo` 或工商代码。

## 候选顺序与停止条件

手动填写/选择公司时只使用该公司；否则取所选地区的内置公司和账号实际资料，去重，最多 20 家。上次成功组合必须与当前源户号、地区匹配才会优先。

场景沿用 [官网户号组件](https://www.95598.cn/osgweb/js/chunk-c32f2cf4.09f9cab9.js)：住宅 `01`、店铺 `02`、电动车 `03`、企事业 `04`、新能源 `05`。它们不是预付费/后付费方式。

场景在外、公司在内：先住宅遍历公司，再店铺等。每轮最多 30 次，串行且请求间至少 1 秒。用户明确类型时不换类型。单位无效只换下一单位，单位必填错误则停止，避免重复相同的协议缺参问题。

仅在空余额或与单位/类型有关的参数错误时继续。登录、短信、验证码、限流、网络、绑定/权限、身份不匹配和未知错误都停止。可在 UI 停止；请求前、等待后和响应后检查取消及配置变更，取消结果不保存。

自动公司匹配要求返回的完整数字户号与输入精确一致；只有金额、掩码或不匹配的户号不会自动保存。显式选择单位时保留原接口兼容：未返回完整户号会显示需核对金额的提示。多户响应仅接受明确匹配的一户。

## 保存与小组件

成功组合按登录账号、户号、地区、单位、类型、查询范围与资料版本隔离。1.4.0 更新查询标识使旧缓存失效。换地区会清空所选单位。小组件只使用已成功保存的一组参数，首次需在设置中查询。

本轮确实完成了公共目录实查；未使用用户账号、短信或实际户号，未完成真实余额查询。
