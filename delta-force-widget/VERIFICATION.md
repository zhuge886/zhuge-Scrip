# 1.3.1 验证记录

## 已完成

- TypeScript 5.8.3 严格检查通过，使用固定提交的公开 Scripting 声明镜像。
- **40 项合成数据测试通过**：包括 1.2.0 的日期、最近日报、休息日缓存、旧版迁移、金额精度、身份隔离及扫码生命周期检查。
- 新增续期凭据提取、访问过期时间、固定 30 天窗口、提前续期、鉴权失败后重试一次、余额错误不触发续期、临时网络失败保留状态。
- 覆盖 refresh_token 轮换后仅写入 Keychain、不发送给游戏查询、不进入普通缓存；拒绝不同身份和异常返回；并发续期合并，退出 / 换号期间不恢复旧凭据，不覆盖更新的 token。
- 检查小号与中号界面节点：普通模式白底，深色“最近收益”文案与绿 / 红收益有反差；正、负、零与无数据状态的文字对白底对比度均至少 4.5:1。透明、模糊及图片透明模式不绘制白底，适配浅色 / 深色外观。无图标、登录横幅和更新时间尾注。
- 核对公开 Scripting 文档中“透明背景小组件”和图片模拟透明的区别；不把删除脚本底板当作自动切换了系统组件类型。

## 验证边界

Linux 无 iPhone、Scripting 原生运行时或用户会话。没有再次执行用户账号的真实扫码 / 续期，也没有观察连续 30 天登录。40 项测试使用合成数据，不能证明账号一定能保持一个月。

微信官方网页文档在当前执行环境返回访问拒绝，未绕过限制。续期请求格式核对公开 OAuth 实现，扫码返回 refresh_token 核对已下载的腾讯 Milo SDK。服务端是否接受该账号的续期，以手机实际查询为准。

## 手机确认

1. 覆盖更新为 **1.3.1**，保留原项目；1.3.0 已启用续期的账号无需再次扫码。
2. 若扫码成功仍没有续期凭据，新版无法强制生成，不应承诺长期免扫码。
3. 先检查现有普通组件：白底上应能看清“最近收益”、日期和绿 / 红金额。再检查 Scripting **“透明背景小组件”**：没有脚本白底，小号 / 中号保留文案与收益。
4. 访问凭据过期后刷新，检查能否自动取到新数据；网络失败应保留原收益与日期。
5. 退出、更换账号后不显示旧账号数据。桌面刷新由 iOS 调度，不能用本机过期时间代替服务端鉴权。
